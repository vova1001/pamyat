# Архитектура сервиса

## Схема
```
Заказчик  →  сайт студии (подписка, чат, личный кабинет)
                ↓
             бэкенд студии  →  Anthropic API (ключ студии)
                ↓
             менеджер (prod/CLAUDE.md) → руководители отделов → специалисты
             (prod/.claude/agents/, память — prod/crew/, общее — prod/common/)
             у каждого заказчика своя сессия и рабочая папка
                ↓
             Vercel / регистратор / Figma — через ключи студии
                ↓
             ответы, ссылки на превью, картинки, QR-коды → чат на сайте
```

- Заказчик ничего не подключает: только платит подписку на сайте, отвечает на вопросы,
  присылает коды подтверждения и оплачивает сервисы по ссылке/QR.
- Подписка claude.ai для сервиса не используется — только API-ключ Anthropic студии (Claude Console).
- Сайт — оболочка: пересылает сообщения и показывает ответы.

## Рекомендуемая основа: Claude Managed Agents
- Команда хранится у Anthropic с версиями: `prod/CLAUDE.md` — главный агент, `prod/.claude/agents/` — агенты отделов,
  `prod/crew/` и `prod/common/` — их память, skills — процедуры.
- Обновили `prod/` в основной ветке → автоматически выпускается новая версия агента.
- У каждого заказчика своя сессия и контейнер — заказчики не видят друг друга и правила.
- Ключи сервисов хранятся в хранилище Anthropic (vault) — их не видит ни агент, ни заказчик.
- Денежный лимит на сессию — под тарифы подписки.

Альтернатива — Claude Agent SDK на своём сервере (больше контроля, больше поддержки). SDK читает агентов
из `.claude/agents/` и умеет вложенные вызовы (менеджер → руководитель → специалист).

## Цена команды
Каждый агент — отдельный запуск модели. Мультиагентные системы расходуют в разы больше токенов,
чем один агент, поэтому продюсер подбирает состав по сложности проекта, а мелочи менеджер делает сам.
Себестоимость измерить на 2–3 тестовых проектах.

## Что делает бэкенд студии
1. Хранит связь «заказчик → его сессия».
2. Хранит проект между визитами (например, отдельный репозиторий на заказчика).
3. Проверяет подписку и лимиты.
4. Показывает не только текст: ссылки на превью, картинки макетов, QR-коды.

## Обучение и прод
- Диалоги заказчиков в `prod/` сами не попадают — складываются на разбор в лабораторию.
- В прод уходит только одобренное владельцем.

## Открытые вопросы
- Где размещать сервер и как оплачивать Anthropic API: в России API официально недоступен.
- Тарифы подписки и себестоимость проекта — измерить на 2–3 тестовых проектах.
