# Черновики памяти команды

Зеркало `prod/crew/`: у каждой роли здесь свой `notes.md`. Замечание про шрифты попадает
дизайнеру, про тон — менеджеру, про видео на сайте — фронтенду. В прод запись уходит только через skill `promote`
и только после «да» владельца: файл роли в `prod/crew/` переписывается начисто, история остаётся здесь и в git.
Весь цикл обучения — `ARCHITECTURE.md`, раздел 3.

## Формат записи
```
### <короткое название>
- Правило: делаем X
- Почему: потому что Y
- Куда: prod/crew/<отдел>/<роль>/<файл>.md (или common/, niches/, components/)
- Источник: владелец | сотрудник (<имя>) | агент
- Подтверждения: <проект-1>, <проект-2>
- Статус: ждёт | ждёт одобрения владельца | предложено | в проде (дата) | отклонено
```

## Правила записи
- Пиши в черновик той роли, чья это зона. Правило для всех ролей — в `management/manager/notes.md` с «Куда: prod/common/…».
- Без имён, телефонов, адресов клиентов.
- Формулируй как правило для любого проекта, а не историю про один.
- Перед новой записью проверь черновики всех ролей: похожее уже есть — не дублируй,
  а добавь проект в «Подтверждения».
- Одну и ту же правку пришлось делать в разных проектах — это кандидат в правило; отметь на разборе.
- Записи до перестройки (2026-10-13) — в `lab/archive/inbox-owner-2026-10.md`, все уже в проде.
