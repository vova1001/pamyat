# Владелец студии

Что агент знает о владельце и его требованиях. Заполняется по ходу работы.
В прод не попадает.

## Цель сервиса
- Агент общается с заказчиками, которым нужен сайт с нуля или доработка готового проекта.
- Полный цикл «от идеи до прода»: бриф → эскизы в Figma → сборка → регистрация в сервисах → оплата → хостинг.
- В `prod/` попадает только выверенная архитектура: этапы, процессы, настройки.
- Всё новое сначала попадает в лабораторию (`lab/`), владелец обучает и контролирует.

## Требования к агенту
- С заказчиками — всегда вежливо и официально.
- Регистрирует заказчиков в сервисах (список согласуется с владельцем).
- Даёт ссылки или QR-коды на оплату.
- Коды подтверждения из SMS/почты заказчик присылает в чат, агент вводит их сам.

## Решения
- 2026-10-06: аккаунты — на заказчика; заказчик платит сервисам напрямую; агент имеет доступ и делает всё в аккаунтах сам.
- 2026-10-06: коды из SMS/почты заказчик присылает в чат, агент вводит.
- 2026-10-06: всё обсуждение с владельцем живёт только в лаборатории (`lab/`, «обучение»). В `prod/` — только поведение агента с заказчиком.
- 2026-10-06: работаем поэтапно, начинаем с этапов 0–1 — общение с заказчиком; владелец играет заказчика.
- 2026-10-06: начался процесс обучения. Что идёт в прод — агент фильтрует сам или спрашивает владельца:
  явное правило владельца с причиной → в прод сразу, с коротким отчётом;
  наблюдение агента или спорное → в `lab/inbox/owner.md` и вопрос владельцу;
  разовое, про одного клиента, или противоречит действующему правилу → в прод не идёт без «да».
- 2026-10-06: модель сервиса — заказчик ничего не подключает, только платит подписку на сайте владельца. Сайт по API (ключ Anthropic владельца) обращается к агенту с правилами из `prod/` и показывает ответы в своём чате.
- 2026-10-06: сотрудники могут обучать агента параллельно — каждый в своей ветке и своём черновике, в прод только с одобрения владельца (`team/rules.md`).
- 2026-10-06: в `prod/` — только работа: этапы и общение с заказчиками. Остальное разложено по `lab/`, `team/`, `service/`.
- 2026-10-07: тест №1 (лендинг вина): макет v3 одобрен как удачный — сохранён в `prod/components/landing-family-winery/`. Скорость видео прокрутки 280 px/с одобрена («видео шикарное»). Все правки теста перенесены в прод.

- 2026-10-13: рамки сужены — только сайты с нуля и доработка готовых (редизайн, разделы, исправления, перенос с конструкторов на свой код). Серверы, внешние сервисы, регистрация, оплата и запуск на домене — отложены (`lab/parked/`).
- 2026-10-13: архитектура — студия из команды агентов, как в реальной компании: менеджер (единственный, кто говорит с заказчиком) → руководители отделов → специалисты. 7 отделов, 22 роли, у каждой своя память. Приоритет — заказчик: понимать его «кривые» просьбы и делать, как он просит.
- 2026-10-13: две одинаковые цепочки — `prod/` (только исполнение, правила переписываются начисто) и `lab/` (зеркало + общение, идеи, ошибки, история). В сервис идёт только `prod/`.
- 2026-10-13: при перестройке всё обученное переносится в нужные слои памяти — ничего не теряется. Крупные изменения — сначала схема владельцу, потом работа; в git — после подтверждения.
- 2026-10-13: в прод — только отфильтрованное и только после подтверждения владельца, без автоматического переноса (даже для правил владельца и подтверждённых в 2+ проектах). Каждый агент занимается только своим делом. Железные правила — `RULES.md`, инструкция — `ARCHITECTURE.md`.
