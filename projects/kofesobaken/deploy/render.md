# Выкладка на Render + Neon (бесплатный старт, кнопка «Deploy to Render»)

Команда в аккаунты заказчика не входит: заказчик сам нажимает кнопку, Render читает `render.yaml` из репозитория
и сам собирает образ `deploy/render/Dockerfile` (nginx + Astro + Go в одном контейнере, порт из `$PORT`).
База — Neon (PostgreSQL). Фото из кабинета — в PostgreSQL (`MEDIA_STORE=postgres`): диска у бесплатного Render нет.
Локально всё как раньше: `docker compose up` (фото — на томе `uploads`).
Ограничения тарифа (засыпание через 15 минут, 750 часов в месяц) — `infra/resources.md`, «Бесплатно за рубежом».

## Какой нужен репозиторий
- **Публичный GitHub-репозиторий только с кодом сайта** — кнопка работает с ним без настроек. Закрытый репозиторий
  кнопка открывает, только если на нём установлено GitHub-приложение Render с доступом из аккаунта заказчика —
  этого с аккаунтом заказчика не сделать без входа в него, поэтому не подходит.
- `render.yaml` — **в корне** репозитория; в корне же `backend/`, `frontend/`, `deploy/` (как в этой папке проекта).
- В публичный репозиторий кладём **только код**: `backend/ frontend/ deploy/ render.yaml docker-compose.yml Makefile
  README.md architecture.md .env.example .gitignore`. Без `brief.md`, `handoff/`, `infra/`, `design/`, `preview/`, `qa/`.
  Секретов в коде нет (проверено). Почта кофейни в коде — та же, что на сайте в контактах.
- Ветка — `main`; `autoDeploy: true` — после каждого слияния в `main` Render пересобирает сайт сам.

Ссылка для заказчика (кнопка):
`https://render.com/deploy?repo=https://github.com/PamyatS/kafesobaka`

## Что нажимает заказчик (у него уже есть аккаунт Neon с базой — задача 11)
1. Открыть ссылку выше → войти в Render или зарегистрироваться (почта и пароль, картинка «я не робот», ссылка из письма).
2. На экране развёртывания заполнить два поля и нажать **Deploy Blueprint**:
   `DATABASE_URL` — строка из Neon (Dashboard → **Connect** → строка подключения; переключатель **Connection pooling**
   выключен, в конце `?sslmode=require`), `ADMIN_EMAIL` — своя почта для входа в кабинет.
3. Когда сервис станет **Live** (5–10 минут): в нём **Environment** → у `ADMIN_PASSWORD` нажать «показать» и
   скопировать → открыть `https://kofesobaken.onrender.com/admin` (адрес — вверху страницы сервиса) → войти этой почтой
   и паролем → придумать свой пароль. Сгенерированный пароль после этого больше не действует.

Остальное Render берёт из `render.yaml`: бесплатный тариф, Франкфурт, проверка `/healthz`, `PAYMENT_WEBHOOK_SECRET` и
`ADMIN_PASSWORD` создаёт сам, адрес сайта (`RENDER_EXTERNAL_URL`) — тоже сам.

## Если что-то пошло не так
- **Забыл пароль.** Сотруднику пароль сбрасывает администратор («Сотрудники» → «Новый пароль»). Администратору:
  Environment → добавить `ADMIN_LINK_ON_START` = `true` → Save → после перезапуска Logs → строка
  `ссылка входа администратора`, поле `link` → открыть → новый пароль → переменную удалить.
- **Сервис не стартует** — Logs: чаще всего неверная `DATABASE_URL` (нет `?sslmode=require`, адрес с `-pooler`).

## Проверить после выкладки (студия, по ссылке на сайт)
- `https://<адрес>/healthz` → `{"status":"ok"}`; сайт и `/admin` открываются.
- Фото, загруженное в кабинете, на месте после перезапуска (Manual Deploy).
- Ограничение попыток входа: в Logs у строк `"msg":"http"` поле `ip` у разных посетителей (телефон и компьютер) разное.
  nginx берёт **последний** адрес из `X-Forwarded-For` — его дописывает прокси Render; то, что прислал сам посетитель,
  Render не очищает, поэтому первому адресу не верим. Если у всех один адрес — сообщить техлиду.

## Проверено в студии
Образ собирается (`docker build --platform linux/amd64 -f deploy/render/Dockerfile .`), стартует за 2 секунды с
внешней PostgreSQL по SSL (`sslmode=require`), `PORT` из окружения; фото переживают пересоздание контейнера;
`render.yaml` проходит официальную схему Render (`https://render.com/schema/render.yaml.json`).

## Переезд потом
База — обычный PostgreSQL: `pg_dump` из Neon → восстановление на новом сервере (фото переедут вместе с базой).
Сайт — `docker compose up -d`; фото можно оставить в базе (`MEDIA_STORE=postgres`). Хранилище S3 — ещё одна
реализация `media.Store` в `backend/internal/media`, остальной код не меняется.
