## Как сайт попадёт на Render
Источник для Render — один из двух ([docs](https://render.com/docs/deploying-an-image)):
1. **Git-репозиторий** (GitHub / GitLab / Bitbucket), подключённый к аккаунту Render, — Render сам собирает по `render.yaml`.
   Репозиторий проекта закрытый и студийный; подключать его к аккаунту заказчика — значит давать заказчику доступ к студийному Git.
2. **Готовый образ из реестра** (GHCR, Docker Hub, GitLab, GAR, ECR) — **выбрано**: студия собирает образ `linux/amd64`
   из `main`, кладёт в закрытый реестр студии (GHCR), в Render — «учётные данные реестра» с токеном только на чтение.
   Плюсы: заказчику не нужен свой GitHub, сборка не тратит бесплатные минуты Render, код не уходит в чужой аккаунт.
   Обновление: новый образ → deploy hook Render (одна команда в `Makefile`).

Переменные окружения сервиса Render: `DATABASE_URL` (строка Neon с `sslmode=require`) и прочие из `.env.example` — вводятся только в Render.
