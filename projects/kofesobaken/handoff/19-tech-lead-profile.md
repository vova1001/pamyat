# 19 · tech-lead · «Мой профиль» в кабинете: сменить почту и пароль

## Задача (пишет менеджер)
- Цель: владелец хочет сам менять почту (логин) и пароль главного администратора; сейчас смены нет (только принудительная).
- Что сделать: в кабинете пункт «Профиль» (для всех ролей): имя, почта, «Сменить пароль». Смена пароля — текущий + новый
  (≥ 8) + повтор; смена почты — текущий пароль + новая почта (уникальна среди входов). После смены — закрыть другие сессии
  этого человека, письмо-уведомление на старую почту (если почта подключена). Ограничение частоты как у входа.
- API по контракту, тесты (неверный текущий пароль = 403, занятая почта = 409, сессии закрываются), e2e — смена пароля.
- Сдать: коммит в ветку проекта (не пушить), тесты зелёные.

## Отчёт (пишет исполнитель)
- Сделано: в кабинете «Профиль» для всех ролей (боковое меню внизу и кнопка в шапке на телефоне): имя и почта,
  «Сменить почту» (новая почта + текущий пароль), «Сменить пароль» (текущий + новый ≥ 8 + повтор).
  API: новый `POST /api/admin/email`; `POST /api/admin/password` — неверный текущий пароль теперь 403 `wrong_password`
  (было 422). Занятая почта — 409. После смены — другие сессии человека закрыты, текущая остаётся; письмо-уведомление
  на прежнюю почту (если подключён Resend). Неверный текущий пароль — в тот же лимит, что вход (8 за 15 мин → 429).
  С временным паролем смена почты недоступна (сначала смена пароля).
- Найдено и закрыто по ходу: если владелец сменит почту, при перезапуске `ADMIN_EMAIL` из окружения создал бы второй
  вход на старую почту (с `ADMIN_PASSWORD` — рабочий). Теперь прежние почты хранятся (`admins.former_emails`,
  миграция 00006, обратимая): второй вход не создаётся, `server admin-link` по старой почте находит администратора и
  шлёт ссылку на нынешнюю.
- Тесты: бэк `go test ./...` на PostgreSQL — зелёные (httpapi 84.8%, service 82.8%); новые `TestProfile` (403/409/422,
  сессии, вход по новой почте/паролю, сотрудник, 429) и `TestProfileEmailAndPassword` (письма, перезапуск со старым
  `ADMIN_EMAIL`, admin-link). e2e: весь набор 19/19 зелёный, новый `profile.spec.ts` — смена пароля на сотруднике
  (неверный текущий, несовпадение, выход второго устройства, вход с новым) + открытие «Профиля» на телефоне.
  Прогон локально без Docker (Docker в среде не запущен): бэк + Astro + прокси вместо nginx; `make test`/`make e2e`
  в Docker не запускал.
- Файлы: `backend/api/openapi.yaml`, `backend/migrations/00006_admin_former_emails.sql`, `backend/queries/auth.sql`,
  `backend/internal/service/{auth,bootstrap,staff}.go`, `backend/internal/httpapi/{server,handlers}.go`, тесты
