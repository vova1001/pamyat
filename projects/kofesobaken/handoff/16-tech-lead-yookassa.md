# 16 · tech-lead · ЮKassa (сначала тестовый магазин)

## Задача (пишет менеджер)
- Цель: заказчица (самозанятая) хочет проверить оплату через ЮKassa в тестовом режиме, потом — боевой.
- Что сделать: `payments.Provider` для ЮKassa API v3 (`PAYMENT_PROVIDER=yookassa`, `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`):
  создание платежа с redirect-подтверждением и `Idempotence-Key`, приём уведомлений (`payment.succeeded`, `payment.canceled`,
  `refund.succeeded`) с проверкой — повторным запросом статуса платежа по API (подписи у ЮKassa нет) и/или IP-списком ЮKassa;
  возврат предоплаты при отмене брони; чек 54-ФЗ — для самозанятого не через ЮKassa (чек в «Мой налог»), поле receipt не слать,
  оставить переключатель на будущее для ИП.
- Тестовый режим = тестовый магазин ЮKassa (те же адреса API, тестовые ключи и тестовые карты). Без ключей — как сейчас, тестовая страница.
- Бесплатный Render засыпает — уведомление ЮKassa его разбудит; обработку сделать идемпотентной и быстрой; плюс при возврате
  гостя на сайт (`/?payment=<id>`) — проверка статуса по API.
- Сдать: коммиты в ветку проекта (не пушить), тесты на httptest-заглушке ЮKassa, `deploy/render.md` — переменные и адрес
  уведомлений `https://kofesobaken.onrender.com/api/payments/webhook` для настройки в личном кабинете ЮKassa.
- Готово, когда: с тестовыми ключами оплата брони/заказа/мероприятия проходит до статуса «оплачено»; без ключей — как раньше.

## Отчёт (пишет исполнитель)
**Сделано (техлид сам — задача на один модуль, быстрее, чем поручать).** API сверено по yookassa.ru/developers
(формат запросов, Idempotence-Key ≤64 символов / 24 ч, уведомления: тип/событие/объект, ответ 200, повторы 24 ч,
подписи нет — проверка повторным запросом статуса и/или IP; тестовый магазин — свои ключи и свой адрес уведомлений).
- `backend/internal/payments/yookassa.go` — адаптер `YooKassa` (`PAYMENT_PROVIDER=yookassa`, `YOOKASSA_SHOP_ID`,
  `YOOKASSA_SECRET_KEY`): `POST /v3/payments` — redirect, `capture: true`, `return_url` = `/?payment=<id>#раздел`,
  описание ≤128 символов, `metadata.payment_id` = наш id, `Idempotence-Key` = наш id платежа; `POST /v3/refunds` —
  вся сумма, ключ `refund-<id ЮKassa>` (повтор не создаёт второй возврат); уведомления `payment.succeeded`,
  `payment.canceled`, `refund.succeeded` — из тела берутся только событие и id, статус/сумма/наш id — повторным
  `GET` к API своими ключами; несовпадение статуса или неизвестный id → 401; прочие события и незавершённый
  платёж → 200 без действий; ЮKassa не ответила → 502 (уведомление придёт повторно).
- Чек 54-ФЗ: `receipt` не отправляется (самозанятая, чек в «Мой налог»); переключатель `YOOKASSA_RECEIPT=true`
  (+ `YOOKASSA_VAT_CODE`, по умолчанию 1 — без НДС) — чек одной позицией с телефоном гостя, для ИП в будущем.
- Возврат гостя: `GET /api/payments/{id}` для платежа в ожидании спрашивает ЮKassa (интерфейс `payments.Checker`)
  и проводит оплату тем же идемпотентным путём, что и уведомление. Обработка уведомлений идемпотентна
  (блокировка строки, повтор — 200 без изменений); `refund.succeeded` отмечает платёж «возвращён».
- Без ключей — как раньше: `PAYMENT_PROVIDER=yookassa` без ключей → предупреждение в журнале и тестовая страница.
  `render.yaml`: `PAYMENT_PROVIDER=yookassa`, `YOOKASSA_*` (sync: false). Обновлены `.env.example`,
  `docker-compose.yml`, `architecture.md`, `backend/api/openapi.yaml` (+ `frontend/src/lib/api.gen.ts`).
- `deploy/render.md`, раздел «Оплата: ЮKassa» — переменные, адрес уведомлений
  `https://kofesobaken.onrender.com/api/payments/webhook` (события payment.succeeded, payment.canceled,
  refund.succeeded; у тестового магазина — в его настройках), проверка тестовой картой, переход на боевой.
- Тесты на httptest-заглушке ЮKassa: `backend/internal/payments/yookassa_test.go` (запрос, идемпотентность,
  подделки, 500/401, возврат, переключатель чека, суммы) и `backend/internal/httpapi/yookassa_test.go` — насквозь
  с PostgreSQL: бронь → оплата по уведомлению → отмена → возврат → refund.succeeded; заказ — «оплачено» по возврату
  гостя без уведомления; мероприятие — отказ и оплата. Все тесты зелёные (`go test ./...` с TEST_DATABASE_URL),
  покрытие: payments 82.7%, service 84.1%, httpapi 84.8%.
- Коммиты `lab:` в текущую ветку, не запушено.

**Не проверено:** настоящий тестовый магазин — нет ключей (вопрос уже в `lab/talk/questions.md`). Проверка по
`deploy/render.md` займёт 10 минут после получения ключей.

**Решения на заметку:**
- Проверка по IP-списку ЮKassa не сделана: на Render адрес отправителя за прокси ненадёжен, а повторный запрос
  к API защищает полностью (поддельное уведомление ничего не меняет).
- Уведомления кофейне (почта/Telegram) после оплаты по-прежнему отправляются внутри обработки (до 15 с) — при
  медленной почте ЮKassa может повторить уведомление, повтор безопасен.
- `golangci-lint`: новых замечаний, кроме уже принятого в проекте `defer resp.Body.Close()` (errcheck), нет.

**Вопросы к заказчице:** ключи тестового магазина ЮKassa (shopId и секретный ключ) — вводит сама в Render
(Environment), не в чат; и адрес уведомлений в настройках тестового магазина — по `deploy/render.md`.

**Сверх задачи (на одобрение):** нет.
