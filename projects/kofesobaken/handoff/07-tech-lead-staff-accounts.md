# 07 · tech-lead · администратор и сотрудники в кабинете

## Задача (пишет менеджер)
- Цель: заказчик: «кабинет — для меня и работников, не для гостей; сделай мне аккаунт администратора, чтобы я создавал
  работников и выдавал им данные для входа; без логина и пароля войти нельзя».
- Решение (по умолчанию, заказчику сообщено):
  - роли: **администратор** (всё + раздел «Сотрудники», «Фото и тексты», «Уведомления») и **сотрудник**
    (брони, заказы, мероприятия и записавшиеся, меню);
  - первый вход: администратор — vovaoleshko05@mail.ru; пароль он придумывает сам на первом экране
    (одноразовая ссылка/код настройки из лога сервера или `ADMIN_PASSWORD` из `.env` — как удобнее, но пароль
    нигде не хранится открыто и не пересылается);
  - администратор создаёт сотрудника: имя, почта, временный пароль (вводит сам и передаёт работнику);
    при первом входе сотрудник обязан сменить пароль; администратор может отключить сотрудника и сбросить пароль;
  - все разделы кабинета и `/api/admin/*` — только после входа, права проверяются на сервере по роли;
    отключённый сотрудник выходит из всех сессий; ограничение частоты входа уже есть — проверить.
- Входные файлы: `architecture.md`, `backend/` (таблицы `admins`, `sessions`), `frontend/` (кабинет), эскиз
  раздела в превью `preview/admin.html` (раздел «Сотрудники» — для вида).
- Что сдать: миграция, API по контракту, раздел «Сотрудники» в стиле кабинета, тесты (роли, отключение, смена
  пароля, доступ без входа = 401), e2e.
- Границы: остальное не трогать; секретов в коде нет.
- Готово, когда: без входа кабинет и API закрыты; сотрудник не видит админских разделов и не может вызвать их API;
  тесты зелёные.
