# 15 · tech-lead · настоящие уведомления: почта (Resend) и Telegram

## Задача (пишет менеджер)
- Цель: заказчица: «почему почта не работает» — брони, заказы, записи должны приходить на почту и в Telegram по-настоящему.
- Почта: адаптер `notify.Channel` для Resend HTTP API (`RESEND_API_KEY`, `MAIL_FROM`, по умолчанию `onboarding@resend.dev`
  до подтверждения домена). Без ключа — как сейчас, в журнал. Письмо — простое HTML: что пришло, имя, телефон, дата/время,
  ссылка в кабинет. Восстановление пароля администратора/сотрудника по почте — если ключ задан (ссылка 1 час).
- Telegram: адаптер Bot API (`TELEGRAM_BOT_TOKEN`); подключение чата владелицы — в кабинете «Уведомления» кнопка
  «Подключить Telegram» → ссылка `t.me/<бот>?start=<одноразовый код>`; бэкенд забирает chat_id по getUpdates (без вебхука —
  бесплатный Render) или по вебхуку, как проще и надёжнее; сообщение с кнопками «Позвонить».
- Ссылка первого входа администратора не должна перевыпускаться при каждом перезапуске (см. `lab`-заметку: живёт до срока
  или использования; новая — только по `admin-link`/`ADMIN_LINK_ON_START`).
- Секретов в коде нет; ключи — только переменные окружения.
- Сдать: коммиты в ветку проекта (не пушить), тесты зелёные (адаптеры — на httptest-заглушках), `deploy/render.md` — какие переменные.
- Готово, когда: с ключами письма и сообщения уходят; без ключей всё работает как раньше.
