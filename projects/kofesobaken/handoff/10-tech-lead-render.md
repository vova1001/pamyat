# 10 · tech-lead · сборка под Render + Neon (бесплатный старт)

## Задача (пишет менеджер)
- Цель: заказчик выбрал бесплатный старт: Render (сайт в Docker) + Neon (PostgreSQL). Условия и риски — `infra/resources.md`,
  раздел «Бесплатно за рубежом».
- Что сделать (после задачи 07):
  - один образ для Render: nginx + Astro + Go в одном контейнере (порт из `$PORT`), `DATABASE_URL` с `sslmode=require`;
  - фото из кабинета — не на диске (на Render он стирается): хранить в PostgreSQL (объём малый) за тем же интерфейсом
    сохранения, чтобы потом перейти на S3 заменой одного модуля;
  - `render.yaml` (Blueprint), инструкция выкладки в `deploy/render.md`; локальный `docker compose up` работает как раньше;
  - страница «Сайт просыпается…» не нужна — просто быстрый старт бинарника и миграций.
- Границы: никаких регистраций; секретов в коде нет; вид не менять.
- Готово, когда: образ собирается, поднимается с внешней PostgreSQL, фото переживают перезапуск, тесты зелёные.

## Отчёт (пишет исполнитель)
- Сделано (с уточнением про кнопку «Deploy to Render»):
  - один образ `deploy/render/Dockerfile`: nginx на `$PORT` → Astro (127.0.0.1:4321) и Go (127.0.0.1:8080), запуск
    `deploy/render/start.sh` под tini; упал любой процесс — контейнер завершается и Render поднимает его заново;
    старт с миграциями — 2 секунды, страница «просыпается» не нужна;
  - фото: интерфейс `media.Store` (`backend/internal/media`), `MEDIA_STORE=disk` (compose, как раньше) или `postgres`
    (таблица `media`, миграция `00003_media.sql`); S3 — ещё одна реализация, остальной код не меняется;
  - база: `DATABASE_URL` с `sslmode=require`; простаивающие соединения закрываются через 4 минуты (Neon засыпает через 5);
  - `render.yaml` для кнопки: `runtime: docker`, `plan: free`, Франкфурт, `/healthz`; `DATABASE_URL` и `ADMIN_EMAIL` —
    `sync: false` (вводит заказчик), `ADMIN_PASSWORD` и `PAYMENT_WEBHOOK_SECRET` — `generateValue`. Сгенерированный
    пароль временный (`ADMIN_PASSWORD_TEMPORARY=true`): после первого входа обязательная смена, после этого он не
    действует, в настройках Render рабочего пароля не остаётся. Адрес сайта Render отдаёт сам (`RENDER_EXTERNAL_URL`);
  - забыл пароль на Render (консоли там нет): `ADMIN_LINK_ON_START=true` → ссылка входа в логах;
  - адрес посетителя на Render: прокси Render дописывает адрес посетителя в конец `X-Forwarded-For` и не очищает то,
    что прислал сам посетитель, поэтому nginx берёт последний адрес; в журнал запросов добавлено поле `ip`.
- Проверка: образ собран `linux/amd64`; поднят с отдельной PostgreSQL только по SSL — работает; фото после
  пересоздания контейнера на месте; путь с подменой имени — 404; сгенерированный пароль → 403 до смены, после смены и
  перезапуска не действует; `render.yaml` проходит официальную схему Render; `make test` зелёный (87%), e2e 15/15,
  `docker compose up` работает как раньше.
- Файлы: `deploy/render/{Dockerfile,start.sh,nginx.conf.template}`, `render.yaml`, `deploy/render.md`,
  `backend/internal/media/`, `backend/migrations/00003_media.sql`, `backend/queries/{media,auth}.sql`,
  `backend/internal/{httpapi,config,service}/…`, `backend/cmd/server/main.go`, `docker-compose.yml`, `.env.example`,
  `README.md`, `architecture.md`.
- Репозиторий для Render (подробно — `deploy/render.md`): **публичный GitHub-репозиторий только с кодом**,
  `render.yaml` в корне. Закрытый кнопка открывает, только если на нём стоит GitHub-приложение Render с доступом из
  аккаунта заказчика, а это без входа в его аккаунт не сделать. Заказчик делает 3 шага: открыть ссылку-кнопку и войти в Render →
  вставить строку Neon и свою почту, «Deploy Blueprint» → когда Live, скопировать `ADMIN_PASSWORD` из Environment,
  войти в /admin и придумать свой пароль.

- Сверх задачи, на одобрение:
  1. `ADMIN_PASSWORD_TEMPORARY` и `ADMIN_LINK_ON_START` (см. выше).
  2. Поле `ip` в журнале запросов — для проверки ограничения попыток входа на Render.
- Проверить в первую очередь: после выкладки, что в логах Render у разных посетителей разный `ip` (`deploy/render.md`,
  раздел «Проверить после выкладки»). Если у всех один адрес, неверные пароли от одного посетителя закроют вход всем.
