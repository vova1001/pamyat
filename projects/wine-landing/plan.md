# План работ

**Тип проекта:** лендинг с нуля, ниша «вино» (Испания, Мадрид), два языка (RU основной, EN), заказ на сайте + кабинет заказчицы.
**Маршрут:** весь цикл; шаги 1–2 пройдены, дизайн-направление согласовано (эскиз v3). План — с шага 4 (ТЗ) до 16.
**Бэкенд:** нужен (Go + PostgreSQL, всё в Docker). Модули:

| Модуль | Что делает |
|---|---|
| Заказы | приём заказа с сайта (имя, фамилия, почта, Telegram, состав `[УТОЧНИТЬ: одно вино или несколько, количество]`), проверка ввода, ограничение частоты, защита от ботов, согласие на обработку данных; список и карточка заказа в кабинете |
| Вход в кабинет | одна учётная запись заказчицы (`[УТОЧНИТЬ: будут ли сотрудники]`), пароль хранится в виде хеша, сессия, ограничение попыток, выход |
| Каталог вин | создать / изменить / скрыть / удалить карточку (название, описание, цена, фото) на RU и EN; изменения сразу видны на сайте |
| Фото | загрузка фото вина, проверка типа и размера, уменьшение под сайт; хранилище — решает техлид (объём малый: том Docker или S3/minio) |
| Автоперевод | RU → EN при сохранении карточки через внешний сервис перевода; EN-поля можно поправить вручную, ручная правка не затирается повторным переводом |
| Уведомления | `[УТОЧНИТЬ: как заказчица узнаёт о новом заказе — письмо, Telegram, только кабинет; нужно ли письмо покупателю]` — модуль включается по ответу |
| Персональные данные | удаление / обезличивание данных покупателя по запросу (GDPR), выгрузка заказов `[УТОЧНИТЬ: нужна ли]` |

**Данные:** до 10 заказов в день (~3 650 в год, несколько МБ в БД); хранить «всегда» — срок проверяет legal (GDPR); карточки вин — `[УТОЧНИТЬ: сколько вин]`, фото — единицы МБ на вино. Ресурсы минимальные: один небольшой сервер, Redis не нужен.

**Внешние сервисы (регистрации на заказчицу, шаг 13):** сервер, адрес сайта, сервис перевода (ключ API — только в окружении), при необходимости — почта для отправки писем, хранилище S3.

### Что делает каждый этап (сверх `common/cycle.md`)
- **4. ТЗ.** Функции посетителя (18+, язык, выбор вина, подбор к блюду, заказ) и заказчицы (вход, заказы, карточки вин, перевод). Сценарии с критериями приёмки по каждому модулю. Раздел «Развитие»: онлайн-оплата, статусы заказов, сотрудники в кабинете, третий язык.
- **5. Дизайн.** Направление не пересматривается. Работа:
  1. ux-designer: перенос структуры эскиза v3 в Figma (375 → 1440) + новые экраны, которых нет в эскизе: форма заказа и её состояния (ошибка, отправлено), переключатель RU/EN, кабинет (вход, список заказов, карточка заказа, список вин, редактор карточки с полями RU/EN и пометкой «переведено автоматически», загрузка фото). Кабинет — тоже с телефона.
  2. ui-designer: макет на переменных и компонентах, 375 / 768 / 1440, реальные тексты, длинные EN-строки; кабинет — простой, на тех же токенах.
  3. photo-editor ∥ ui: обработка фото вин заказчицы, когда придут; стоковые — только временно, люди не выдаются за семью.
  4. motion-designer: `design/motion.md` по анимациям v3 (заставка, зум видео, шторка, бегущая строка, параллакс).
  5. art-director: `design-spec.md`. Проверка первого экрана на телефоне (заголовок и кнопка — на первом экране).
- **6. Тексты.** Все тексты лендинга на RU → ворота → translator: EN. SEO — на оба языка (hreflang, мета). Тексты формы, согласия, 18+, писем — тоже.
- **7. Архитектура.** Как карточки «сразу появляются на сайте» (серверная отрисовка или запрос к API — решает техлид); выбор сервиса перевода (2 варианта с ценой — в `infra/options.md`); где хранить фото.
- **9. Фронт ∥ бэк.** Фронтенд до готовности бэка — на заглушках по контракту. Кабинет — закрыт от поисковиков.
- **11. Качество.** security: вход в кабинет, загрузка файлов, форма (спам, инъекции), секреты. legal: продажа алкоголя онлайн в Испании, подтверждение возраста, GDPR (согласие, политика, срок хранения, cookies), лицензии фото (CC BY — авторы в подвале). qa: сценарии на RU и EN, автоперевод, 18+. performance: видео на первом экране, вес страниц. Видео прокрутки — покадрово, 8–10 кадров проверить до показа.
- **13. Сервисы.** Сервер, адрес сайта, сервис перевода (+ почта для писем, S3 — если выбраны на шаге 7).

## Особые требования
- **Ниша и закон:** окно 18+ и предупреждение в подвале; без призывов пить и обещаний пользы; legal подключается уже на шаге 4 (короткая консультация по закону о продаже и GDPR; по цепочке менеджер → qa-lead → legal, ответ — во входные аналитику), а не только на 11.
- **Языки:** RU + EN по всему сайту, включая форму, ошибки, письма, 18+, политику; EN карточек — автоперевод с правкой.
- **Сайт-пример высокого уровня** (vinabani.ru): видео, анимации, заставка → motion-designer и performance обязательны.
- **Минимум данных покупателя:** только имя, фамилия, почта, Telegram; согласие у формы.

## Риски и [УТОЧНИТЬ]
1. **Противоречие в брифе:** п. 5 — заказ на сайте; п. 17 и эскиз v3 (блок 9) — заказ через соцсети. `[УТОЧНИТЬ: остаются ли соцсети как второй способ заказа]`. Блок «Заказ» в дизайне меняется в любом случае.
2. **Оплата и доставка:** `[УТОЧНИТЬ: как оплачивает покупатель (при получении, переводом, онлайн); куда доставляете (Мадрид, Испания, ЕС)]`. Онлайн-оплата не планируется до ответа и проверки legal.
3. **Закон Испании:** онлайн-продажа алкоголя и подтверждение возраста при доставке — проверка legal; итог может изменить форму заказа.
4. **Срок хранения «всегда»** противоречит GDPR (хранение не дольше нужного) — legal даёт срок, менеджер согласует с заказчицей.
5. **Статус дизайна:** в `design/links.md` эскиз v3 — «показан заказчику», `design/approved/` пусто; фишки v3 (заставка, подбор вина к блюду, год на винограднике, меню) были «на одобрение». `[УТОЧНИТЬ: одобрены ли все фишки v3]`. Блок 8 «В гости» — `[УТОЧНИТЬ: принимаете ли гостей]`.
6. **Нет фактов:** контакты, цены, вина, история семьи, логотип и цвета, адрес сайта — `[УТОЧНИТЬ]`. Без логотипа — подключить brand-designer.
7. **Свои фото:** сейчас временные стоковые; фото бутылок заказчица загружает сама — нужны требования к фото (размер, фон) в кабинете.
8. **Сервис перевода** — платный внешний сервис с ключом; при его отказе карточка сохраняется без EN с пометкой «перевести вручную».
