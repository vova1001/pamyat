# 11 · tech-lead · платежи (песочница), сессии, баланс токенов, мост к агенту, богатый чат

## Задача
- **Цель:** внутренняя логика сервиса Lumen в ветке `agent-bridge` `/home/user/ai-studio` (от `lumen`).
- **Решения заказчика:** платежи — сначала тестовый магазин ЮKassa; ключа Claude пока нет → заглушка + ответы
  администратора; потом один ключ студии, токены клиентам начисляются из «пула» студии после успешного вебхука оплаты,
  ответы агента списывают токены с баланса клиента.
- **Что сдать:**
  1. **Платежи (песочница):** ключи ЮKassa (shopId, секретный ключ) вводит владелец в админке «Настройки → Платежи»
     защищённой формой (шифровать `ENCRYPTION_KEY`, значение после сохранения не показывать, только «задан ··· 4 последних»);
     env-переменные остаются запасным вариантом. Вебхук `/api/payments/webhook/yookassa` — проверка статуса запросом к
     API ЮKassa (не доверять телу), идемпотентность; продление (сохранённый способ оплаты), отмена, пакеты токенов;
     опрос зависших `pending` (как в памяти бэкенда — «payment sweep»). Режим «тест/боевой» видно в админке.
  2. **Сессии агента:** таблица сессий (клиент, проект, статус: active / waiting_client / agent_thinking / human /
     closed, кто ведёт: agent|human, провайдер, токены вход/выход, последняя активность). Админка: раздел «Сессии» —
     список с фильтрами и поиском, карточка сессии с чатом, «перехватить» / «вернуть агенту».
  3. **Мост к агенту:** интерфейс провайдера в Go (`Reply(ctx, session, history) → поток событий: текст, структурные
     блоки, использование токенов`), реализации: `stub` (сценарий брифа с кнопками: тип сайта, ниша, что есть, сроки →
     «передаю администратору»), `anthropic` (Messages API, модель из настроек, стриминг, инструменты для структурных
     блоков: quick_replies, choice_cards, form, payment, preview; включается, когда ключ задан в админке защищённой
     формой). Очередь/воркер, чтобы ответ не держал HTTP-запрос; SSE или опрос для «печатает».
  4. **Баланс токенов и пул студии:** пул (сколько куплено у провайдера, вносит владелец в админке), начисление клиенту
     из пула при успешной оплате подписки/пакета (вебхук), списание за ответы по `token_ledger`; нулевой баланс → агент
     не отвечает, клиенту — карточка «докупить», админу — уведомление. Админка: пул, выдано, осталось.
  5. **Структурные сообщения:** формат блоков в БД и API (тип + данные + ответ клиента), отправка ответа на кнопку/форму,
     админ может отправлять такие блоки из конструктора и шаблонов.
  6. **Интерфейс чата** — по `../design/design-spec-chat.md` (готовит арт-директор параллельно; начни с бэка).
- **Окружение:** как в задаче 09 (`/tmp/pgais/run-api.sh`, `next start :3000`, коды в `/tmp/pgais/api.log`).
  Тестовые ключи ЮKassa у менеджера нет — проверь вебхук и продление на имитации ответов API ЮKassa (тест-сервер в тестах)
  и dev-провайдере; живую проверку с песочницей сделает менеджер после выкладки.
- **Границы:** секреты — никогда в код, логи и файлы; без тяжёлых библиотек; правило студии — только свои элементы.
- **Когда готово — СТРОГО:** весь функционал проверен в браузере (оплата dev → вебхук → токены начислены; сессия видна
  в админке; заглушка ведёт бриф кнопками; перехват/возврат; форма и карточки в чате; нулевой баланс), go test (новые тесты
  на вебхук, начисление, списание, провайдер stub), lint, typecheck, build; 375/1440, обе темы. Коммиты в `agent-bridge`, push.

## Отчёт
- **Сделано (сам, без подагентов: в этой сессии нет инструмента их запуска).** Ветка `agent-bridge`, коммиты
  `dd5d82c`…`3665145`, запушено в origin. Формат блоков — по `design-spec-chat.md` п.1 (`meta.blocks`, `meta.answers`,
  `reply` в `POST /api/chat`), чтобы фронту не нужен был переводчик. Решения менеджера учтены: счёт в чате — только тариф
  или пакет (своей суммы нет); стартеры пустого чата — типовые тексты; дополнения п.21 спеки сделаны.
  1. **Платежи:** «Настройки → Платежи» — выбор «тестовая страница студии / ЮKassa», shopId и секретный ключ защищённой
     формой (AES-GCM на `ENCRYPTION_KEY`, после сохранения — «задан ··· 4 последних», значение не возвращается ни в API,
     ни в журнал, ни в лог); env — запасной вариант; режим тест/боевой — по ключу и по проверке `GET /me` («Проверить
     подключение»); адрес вебхука на странице. Вебхук `/api/payments/webhook/yookassa`: статус берётся только из API ЮKassa,
     сверяются сумма, валюта и наш id заказа; идемпотентно. Продление сохранённым способом, отмена, пакеты — как были,
     покрыты тестами. Фоновая сверка (payment sweep): <2 ч — раз в минуту, 2–24 ч — раз в 15 мин, старше суток — закрытие
     тем же путём, что и вебхук.
  2. **Сессии:** статусы active / waiting_client / agent_thinking / human / error / closed, кто ведёт (agent|human),
     провайдер, токены вход/выход, последняя активность (миграция `004_agent_bridge.sql`, старые paused → human).
     Админка: раздел «Сессии» (фильтры, поиск, опрос 10 с, полоса «ждёт человека», карточки на 375), карточка
     `/admin/sessions/[id]` и панель в карточке заказчика: «Агент / Я» (перехват без подтверждения, возврат — своим диалогом),
     токены, остаток, этап, ошибка с «Перезапустить агента», «Закрыть сессию». Ответ админа перехватывает чат.
  3. **Мост:** `api/internal/agent`: `Provider.Reply(ctx, session, history) <-chan Event` (status, text, block, usage,
     handoff, error); `stub` — бриф карточками/кнопками/формой: тип сайта → ниша → что есть → сроки и связь → итог списком и
     «передаю администратору» (сессия → human, обращение); `anthropic` — Messages API со стримингом, инструменты show_choice /
     show_cards / show_form / show_payment / show_preview / handoff_to_human, модель и ключ в «Настройки → Агент» (включается
     только с ключом). Очередь `agent_jobs` + воркер (4 параллельно, повтор 3 раза, затем статус error + обращение),
     ответ потоком SSE из `POST /api/chat` и опросом (`typing` в ленте), «Стоп» — `POST /api/chat/stop`.
  4. **Токены:** пул студии («Настройки → Токены»: куплено, выдано, осталось, израсходовано, история); выдача клиенту из пула
     в той же транзакции, что подтверждение оплаты (повторный вебхук пул не трогает); списание за каждый ответ по
     `token_ledger`. Ноль — агент не отвечает, клиенту сразу карточка «докупить» (пакет), поле ввода → «Лимит закончился /
     Пополнить», админам уведомление; после оплаты агент продолжает сам.
  5. **Блоки:** проверка данных и ответов на сервере (варианты из списка, почта, телефон, код из СМС не сохраняется),
     ответ — сообщение клиента с человеческим текстом; админ отправляет блоки из конструктора (кнопки, карточки, форма,
     счёт, версия) с живым превью «Так увидит заказчик»; шаблоны с блоками («В шаблоны» из чата, поиск, «/» в пустом поле).
  6. **Интерфейс чата** по спецификации: `web/src/components/chat/` (лента с группами и разделителями дней, markdown,
     блоки, файлы галереей и свой просмотрщик со свайпом и своим видеоплеером, «печатает/думает», плашка «отвечает человек»,
     ошибка отправки с «Повторить», пустой чат со стартерами, поле ввода с авто-высотой, вставкой и перетаскиванием на весь
     чат, миниатюрами с прогрессом), `CodeField` в `forms.tsx`, токены `--ok`, анимации.

## Приёмка
Принято менеджером после своей проверки: вход → dev-оплата → токены → бриф заглушкой (карточки, кнопки, множественный выбор, форма) → передача администратору; «Сессии» и карточка сессии в админке (кто ведёт, токены, провайдер); ошибок консоли нет. Поправлено: модель по умолчанию claude-sonnet-5-5, превью без markdown. Пул в минус — оставить, владельцу уведомление (решение менеджера, сказать заказчику). Живая песочница ЮKassa — после выкладки, ключи вводит заказчик в админке.
