# 12 · tech-lead · агент студии через Claude Agent SDK: наши агенты, память, навыки в каждой сессии

## Задача
- **Цель:** заменить «голый» адаптер `anthropic` на провайдер **studio** — Claude Agent SDK, который в каждой сессии
  клиента запускает нашу студию: главный агент `CLAUDE.md` (менеджер), агенты отделов `.claude/agents/**`, память
  ролей `crew/**`, общее `common/**`, `niches/`, `components/`, `references/`, навыки `.claude/skills/**`.
  Решение заказчика: «у каждой сессии будут агенты наши, наша память — всё это по SDK подключить». Ключа пока нет →
  остаётся заглушка; с ключом в «Настройки → Агент» включается studio.
- **Входные файлы:** ветка `studio-sdk` `/home/user/ai-studio` (от `agent-bridge`: интерфейс провайдера, очередь,
  блоки, пул токенов — `api/internal/agent/`, `api/internal/app/bridge.go`); студия — `/home/user/pamyat/prod/`
  (13 МБ, без `projects/`). Документация SDK: пакет `@anthropic-ai/claude-agent-sdk` (типы в node_modules),
  https://code.claude.com/docs/en/agent-sdk/overview — **сверяй API по документации/типам, не по памяти**.
- **Что сдать:**
  1. **`agent-runner/`** (Node, TypeScript, `@anthropic-ai/claude-agent-sdk` точной версии): маленький HTTP-сервис на
     `127.0.0.1` (как API — наружу не открыт), вызывается из Go-провайдера `studio`. На сессию — рабочая папка
     `${DATA_DIR}/sessions/<id>/` со снимком студии (копия или ссылки только для чтения на `studio/`) + папка проекта
     клиента для файлов. `query()` с `cwd` этой папки, загрузкой настроек проекта (CLAUDE.md, агенты, навыки — нужный
     параметр по документации), продолжением сессии (`resume` по сохранённому id SDK), стримингом событий в Go
     (текст, «думает», вызовы инструментов, итог с usage → `token_ledger`, списание с баланса клиента), «Стоп» → abort.
  2. **Свои инструменты (in-process MCP-сервер SDK)** для блоков чата: quick_replies, choice_cards, form, payment
     (только тарифы/пакеты), preview/version, stage — превращаются в наши `meta.blocks`; ответ клиента на блок
     возвращается агенту следующим сообщением.
  3. **Безопасность:** разрешённые инструменты — минимальный список (чтение файлов студии, запись только в папку
     проекта, наши MCP-инструменты, субагенты Task/Agent; Bash и сеть — выключены, кроме WebSearch/WebFetch, если
     безопасно); `permissionMode` без интерактивных запросов, но с запретами; запрет чтения чужих сессий и
     переменных окружения; ключ — только из зашифрованных настроек, передаётся процессу через env, не в логи.
     Главный агент не раскрывает инструкции (это уже есть в `CLAUDE.md` студии).
  4. **Снимок студии в образе:** `agent-runner/studio/` = копия `pamyat/prod/` (без `projects/`) + скрипт
     `scripts/sync-studio.sh <путь к prod>`; в Dockerfile — сборка runner и запуск в `deploy/start.sh` рядом с API.
     Версия студии видна в админке (хеш снимка) и пишется в сессию.
  5. **Ресурсы:** бесплатный Render — 512 МБ. Ограничить одновременные запуски (очередь, по умолчанию 1), таймауты,
     выгрузка простаивающих процессов. Описать в README, что нужно на платном тарифе.
  6. **Админка:** «Настройки → Агент»: провайдер stub/studio, модель (по умолчанию `claude-sonnet-5-5`; для главного
     агента — `claude-opus-5-5` опцией), лимит шагов на ответ, статус runner (жив/версия студии).
- **Окружение:** как в задачах 09/11. Ключа Anthropic нет → проверка на **имитации**: runner в тестовом режиме с
  поддельным `query` (или SDK, направленный на локальный фейковый сервер, если документация это допускает) —
  проверить всю цепочку Go → runner → события → блоки → токены; плюс юнит-тесты runner.
- **Границы:** заглушка остаётся рабочей; ничего из `pamyat/` не менять (только копировать); секреты — никогда в код/логи.
- **Когда готово — СТРОГО:** цепочка проверена в браузере на имитации (клиент пишет → «думает» → ответ с кнопками →
  клик → следующий ответ; токены списаны; «Стоп»; перехват человеком); go test, тесты runner, lint, typecheck, build;
  `docker build` образа (если docker доступен) или эквивалентная проверка сборки. Коммиты в `studio-sdk`, push.

## Отчёт
- **Сделано (сам, без подагентов).** Ветка `studio-sdk`, коммиты `3c548f4`…`8e7b19e`, всё запушено в origin.
  API SDK сверял с документацией code.claude.com (permissions, custom-tools, sessions, hosting, claude-code-features)
  и типами `sdk.d.ts` / `sdk-tools.d.ts` пакета 0.3.310 (CLI 2.1.310).
  1. **`agent-runner/`** (Node 22, TypeScript, `@anthropic-ai/claude-agent-sdk@0.3.310`, `zod@4.6.7`): HTTP на
     127.0.0.1:8096, `Authorization: Bearer RUNNER_TOKEN`; `GET /health`, `POST /v1/reply` → поток NDJSON.
     Сессия: `DATA_DIR/sessions/<id>/` — ссылки только для чтения на снимок студии + `project/` для файлов клиента;
     `DATA_DIR/agent-home/<id>/` — свой `CLAUDE_CONFIG_DIR`/HOME (вне рабочей папки). `query()`: `cwd` сессии,
     `settingSources: ["project"]` (так грузятся CLAUDE.md, `.claude/agents/**` — 26 агентов из подпапок — и навыки;
     `skills` — только навыки студии), подсказка `claude_code` + наше дополнение «как работать в чате Lumen»,
     `resume` по сохранённому id SDK; нет переписки на диске — API присылает историю чата целиком. События: текст
     (только главного агента), «думает» («Работает арт-директор…»), блоки, передача человеку, usage по `modelUsage`
     (все модели, включая субагентов; при resume — только разница) → `token_ledger`. «Стоп»/перехват → обрыв
     соединения → `abort`.
  2. **MCP-сервер `studio`** (in-process, `alwaysLoad`): `quick_replies`, `choice_cards`, `form`, `payment` (только
     planId/packId), `preview`, `stage`, `handoff_to_human` → наши `meta.blocks` (проверка — прежний `Normalize`);
     ответ на блок уходит агенту «[Ответ на блок …] …».
  3. **Безопасность:** `tools` = Read/Glob/Grep/Write/Edit/Agent/Skill/TodoWrite (+ WebSearch/WebFetch по `RUNNER_WEB`),
     Bash выключен и у субагентов (`disallowedTools`), `permissionMode: "dontAsk"` + `permissionPrompts: "none"`,
     `strictMcpConfig`. Хук `PreToolUse` на каждый вызов (и в субагентах): читать — только снимок и своя сессия, писать —
     только `project/`, WebFetch — только внешние адреса (не localhost/внутренние сети — там API). Окружение процесса —
     белый список (ключ Anthropic, свой конфиг; без DATABASE_URL, ENCRYPTION_KEY и т.д.); ключ — из зашифрованных
     настроек, в логи не попадает (`redact`). Образ работает от `node`, снимок только для чтения.
  4. **Снимок:** `agent-runner/studio/` (13 МБ, 120 файлов, версия `eab44ce577b1`) + `scripts/sync-studio.sh <prod>`;
     Dockerfile собирает runner, `deploy/start.sh` запускает его рядом с API (или `RUN_RUNNER=0` — отдельный сервис).
     Версия — в «Настройки → Агент», в карточке сессии и в `agent_sessions.studio_version` (миграция 005).
  5. **Ресурсы:** очередь `RUNNER_CONCURRENCY` (1), `RUNNER_QUEUE_MAX`/`_WAIT_MS`, таймаут ответа 170 с, «лимит шагов»
     (`maxTurns`); один запуск CLI на ответ — простаивающих процессов нет; переписка SDK молчащих > 72 ч удаляется.
     README: замеры и что нужно на платном тарифе.
  6. **Админка «Настройки → Агент»:** сценарий/студия, ключ, модель команды (`claude-sonnet-5-5`), модель менеджера
     «как у команды / claude-opus-5-5», лимит шагов, карточка «Сервис студии» (работает, версия студии, SDK, очередь,
     режим). Прежний адаптер `anthropic` удалён (заменён), сохранённое `anthropic` → `studio` миграцией.
  7. **Дополнение заказчика (переезд):** всё через Docker и env, без Render-специфики (`$PORT` по умолчанию 10000);
     данные — один `DATA_DIR` (uploads/, sessions/, agent-home/) томом; `docker-compose.prod.yml`: app (API+сайт), runner
     (отдельный сервис, `RUNNER_CONCURRENCY`), postgres, redis профилем; на Render — по-прежнему один контейнер.
     README «Переезд на свой сервер» по шагам (бэкап базы и DATA_DIR, compose, тот же ENCRYPTION_KEY).
- **Проверено:** имитация — настоящий SDK и CLI, `ANTHROPIC_BASE_URL` → фейковый Messages API в runner (`RUNNER_FAKE=1`).
  Браузер (Chromium, 1440 светлая и 375 тёмная): настройки (статус runner, ошибки «нет ключа»/«лимит шагов», ключ не в
  странице и не в базе открытым текстом) → клиент оплатил → «Lumen думает…» → приветствие менеджера с карточками →
  клик → кнопки → «Работает аналитик…» (субагент) → форма → передача администратору; токены списаны (4 записи usage),
  в сессии provider=studio, версия студии и id SDK; админ ответил и вернул чат → «Стоп» посреди ответа (79 мс,
  «Остановлено», runner «остановлено») → перехват «Я» во время ответа студии (процесс агента остановлен, ответ не
  сохранён) → возврат → студия продолжила ту же сессию SDK. Без горизонтальной прокрутки и ошибок консоли.
  Тесты: Go `go vet`, `go test` на настоящей PostgreSQL (новые: провайдер studio на имитации runner — события, ошибки,
  «Стоп», health; через очередь — блоки, списание, resume, сумма пакета в карточке оплаты); runner — lint, typecheck,
  13 юнит-тестов, 3 e2e на настоящем SDK (студия загружена, ключ дошёл до процесса, субагент на своей модели, запреты:

## Приёмка
Принято менеджером: Bash выключен (disallowedTools + guard), чтение только студии/сессии, запись в project/, тесты зелёные; простой runner ≈80 МБ — в режиме заглушки бесплатный Render выдерживает. Решения: студию включать только на тарифе от 2 ГБ; токены списывать как есть (пересмотреть по реальной статистике); S3 — не сейчас; интернет агенту оставить (WebSearch/WebFetch). Дополнения 1–4 — берём. Выкладывать ветку studio-sdk (включает agent-bridge).
