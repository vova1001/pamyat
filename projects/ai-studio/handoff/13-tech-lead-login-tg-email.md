# 13 · tech-lead · вход через Telegram + почта для всех без домена

## Задача
- **Цель:** пока нет домена, код по почте (Resend) доходит только до одного адреса. Заказчик: «сделаем 2 варианта —
  через Telegram или через почту». Ветка `tg-login` `/home/user/ai-studio` (от `studio-sdk`).
- **Что сдать:**
  1. **Вход через Telegram** (deep-link, без виджета и без домена): на `/login` кнопка «Войти через Telegram» → сайт
     создаёт одноразовый токен входа (короткий срок, хеш в БД) → открывает `https://t.me/<bot>?start=login_<token>` →
     бот (уже есть вебхук `/api/telegram/webhook`, секрет `TELEGRAM_WEBHOOK_SECRET`) получает /start, привязывает
     telegram id и отвечает кнопкой «Подтвердить вход» (или сразу подтверждает) → страница входа опросом/SSE видит
     подтверждение и логинит. Согласие (оферта + ПДн) — те же две галочки до нажатия. Новый пользователь создаётся по
     telegram id (имя и @username из Telegram, почта пустая — потом можно добавить в профиле). Существующий — по
     привязке. В профиле: «Telegram привязан / привязать», «почта привязана / добавить». Админка: Telegram в карточке
     пользователя. Установка вебхука бота: команда `api telegram-setup` или авто при старте, если задан токен
     (`setWebhook` на `${APP_URL}/api/telegram/webhook` с secret_token). `TELEGRAM_BOT_USERNAME` — брать через `getMe`,
     если не задан. Защита: токен одноразовый, привязан к браузерной сессии (cookie), срок 5–10 минут, лимит попыток.
  2. **Почта без домена:** провайдер **Brevo** (HTTP API, `BREVO_API_KEY`, отправитель `MAIL_FROM`, например
     studio_worker@mail.ru — подтверждается в Brevo). Порядок выбора: Brevo → Resend → SMTP → лог. Документировать в README.
  3. Если почтовый провайдер вернул ошибку «нельзя этому адресату» — на странице входа понятное сообщение и
     предложение «Войти через Telegram», а не немое «Отправили код».
- **Окружение:** как в задачах 09–12. Бота в тесте нет — имитация Telegram API (тест-сервер) + юнит-тесты;
  живую проверку сделает менеджер, когда заказчик вставит токен в Render.
- **Границы:** стиль Lumen, только свои элементы; секреты не в код.
- **Когда готово — СТРОГО:** в браузере на имитации: вход через Telegram новым и существующим пользователем, отказ по
  просроченному токену, привязка в профиле; вход по почте как раньше; go test, lint, typecheck, build. Коммиты в
  `tg-login`, push.

## Отчёт
- **Сделано (сам, без подагентов).** Ветка `tg-login`, коммиты `4562aa3` (API) и `57e36ca` (сайт, README), запушены.
  1. **Вход через Telegram:** `POST /api/auth/telegram/start` (обе галочки обязательны, лимит 20/15 мин с адреса) →
     токен 32 символа, в базе только HMAC (таблица `telegram_tokens`, миграция 006), 10 минут, привязан к браузеру
     HttpOnly-cookie `tg_login` → `t.me/<бот>?start=login_<токен>` (≤ 64 символов). Бот на `/start` присылает кнопку
     «Подтвердить вход»; нажать может только тот же Telegram, что открыл ссылку. Страница входа опрашивает
     `/api/auth/telegram/status` раз в 2 с (и сразу при возврате на вкладку) и открывает кабинет; сессия выдаётся
     один раз, лимит 400 опросов. Новый пользователь — по Telegram id (имя и @username из Telegram, почта пустая:
     уникальность почты теперь только у непустых); существующий — по привязке (Telegram уникален). 2FA админов — как раньше.
  2. **Профиль «Способы входа»:** почта «привязана / добавить» (код на новый адрес, проверка занятости),
     Telegram «привязан @username / привязать / отключить» (отключить без почты нельзя). Привязка переделана на
     токен в базе `link_<токен>`: прежняя JWT-ссылка была длиннее 64 символов — Telegram её бы обрезал.
     Админка: почта и @username в карточке, поиск по @username, в списке без почты — «Telegram @…».
  3. **Вебхук:** ставится сам при каждом старте API, если задан токен (`setWebhook` на
     `${APP_URL}/api/telegram/webhook`, `secret_token`, только https); `APP_URL` не задан → `RENDER_EXTERNAL_URL`.
     Вручную — `api telegram-setup`. Имя бота — `TELEGRAM_BOT_USERNAME` или `getMe`.
  4. **Почта:** Brevo HTTP API (`BREVO_API_KEY`, `MAIL_FROM`), порядок Brevo → Resend → SMTP → лог. Отказ сервиса
     (4xx, SMTP 5xx) → код `mail_rejected`: «Не получилось отправить письмо на этот адрес…» + «Войдите через Telegram»;
     временная ошибка — «попробуйте через минуту». README («Вход: почта или Telegram») и `.env.example` дополнены.
- **Проверено:** `go vet`, `go test ./...` на базе (6 новых тестов на имитации Bot API и Brevo: новый/существующий,
  чужой Telegram не подтверждает, без cookie не пускает, повтор, просрочка, лимит опросов, привязка, занятый Telegram,
  добавление почты, setWebhook/getMe, классификация ошибок почты), `tsc`, `eslint`, `next build`.
  Браузер (Chromium 1440 и 375 тёмная) на имитации Telegram + Brevo, вебхук через сайт :3000: новый пользователь через
  Telegram → кабинет; профиль без почты → добавил почту кодом (письмо через имитацию Brevo); выход → вход тем же
  Telegram (дубля нет); просроченный токен → «Ссылка устарела», не пустило; вход по почте → привязка Telegram в
  профиле → вход через Telegram в этот же аккаунт; отказ почты → сообщение и Telegram; карточка в админке. 19/19.
