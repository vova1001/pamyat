# Правила совместной работы

## Ветки
- Основная ветка защищена. Напрямую в неё никто не пушит.
- Каждый работает в своей ветке; в основную — только через pull request.
- Pull request одобряет и сливает только владелец.

## Кто что может
| Действие | Владелец | Сотрудник |
|---|---|---|
| Добавлять записи в черновики ролей `lab/crew/` (со своим именем в источнике) | да | да |
| Добавлять тестовых клиентов в `lab/test-clients/` | да | да |
| Вести проекты в `projects/` | да | да |
| Одобрить перенос правила в `prod/` (после фильтра `promote`) | да | нет |
| Менять `prod/CLAUDE.md` и состав агентов `prod/.claude/agents/` | только сам владелец | нет |
| Отклонять кандидатов (`lab/rejected.md`) | да | нет |

## Как правило сотрудника попадает в прод
1. Агент записывает его в черновик нужной роли `lab/crew/<отдел>/<роль>/notes.md` со статусом «ждёт одобрения владельца».
2. Сотрудник открывает pull request.
3. Владелец смотрит: одобряет → агент переносит через skill `promote` (фильтр и «да» владельца — как для любого правила);
   отклоняет → запись уходит в `lab/rejected.md` с причиной.

## Порядок
- Одно изменение прода — один коммит `prod: …`, чтобы его можно было откатить отдельно.
- Изменения лаборатории — коммиты `lab: …`, команды — `team: …`, сервиса — `service: …`.
- Противоречие между правилами разных людей решает владелец.
