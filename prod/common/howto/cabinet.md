# Кабинет заказчика: вход, роли, профиль

**Когда:** заказчик сам меняет контент или видит заявки, брони, заказы.

## Как устроено
- Вход по почте и паролю; без входа кабинет и все `/api/admin/*` отвечают 401, права проверяет сервер (403).
- Роли: **администратор** — всё, включая тексты сайта, уведомления, сотрудников; **сотрудник** — брони, заказы,
  меню, мероприятия, вопросы. Разделы, недоступные роли, не показываются в меню.
- **Первый вход администратора** — одноразовая ссылка (хранится только хэш, срок 72 часа, не перевыпускается при
  перезапуске); пароль придумывает сам заказчик — пароль не передаётся ни через кого.
- **Сотрудники**: администратор создаёт вход (имя, почта, временный пароль) → при первом входе сотрудник обязан сменить
  пароль; отключение и сброс пароля закрывают все сессии человека.
- **Профиль** у каждого: смена почты (с текущим паролем, почта уникальна) и пароля (текущий + новый ≥ 8 + повтор),
  после смены — закрыть остальные сессии и письмо на прежнюю почту.
- «Забыли пароль?» — ссылка на почту на 1 час, если подключена отправка писем.
- Пароли — bcrypt; сессии — в БД только хэш токена; ограничение частоты входа по адресу и по почте; адрес клиента —
  из надёжного заголовка прокси, не из подставляемого.
