# Механики — как это делается

Проверенные способы сделать повторяющиеся вещи. Каждая механика: когда нужна → как устроено → как делать по шагам →
на чём спотыкаются. Перед задачей роль смотрит, нет ли здесь готовой механики; после проекта новые механики
добавляются сюда (`common/cycle.md`, шаг 16).

| Механика | Файл | Кто использует |
|---|---|---|
| Карта «как пройти» (2D/3D) | `map.md` | UI-дизайнер, фронтенд |
| Репозиторий проекта на GitHub | `git-repo.md` | техлид, devops |
| Выкладка сайта на хостинг | `deploy.md` | devops, sysadmin, техлид |
| Подключение внешних сервисов | `services.md` | менеджер, devops, менеджер по сервисам |
| Кабинет заказчика: вход, роли, профиль | `cabinet.md` | аналитик, техлид, бэкенд, фронтенд |
| Оплата на сайте | `payments.md` | бэкенд, менеджер по сервисам |
| Уведомления: почта и Telegram | `notifications.md` | бэкенд, менеджер по сервисам |
| Вопросы гостей: форма и бот | `questions.md` | аналитик, фронтенд, бэкенд |
| Превью для заказчика до своего адреса | `preview.md` | менеджер, фронтенд, дизайн |
| Проверка адаптива и ссылок | `responsive-check.md` | фронтенд, отдел качества |
