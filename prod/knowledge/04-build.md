# Этап 5. Сборка

## Порядок
1. Проверь `components/` — что можно переиспользовать.
2. Задай дизайн-токены (цвета, шрифты, отступы) в одном месте конфигурации.
3. Собирай блоки сверху вниз, сначала мобильная версия.
4. Подставь тексты из `content.md`. Заглушек в готовом сайте быть не должно.
5. Запусти локально, сделай скриншоты 375px, 768px, 1440px. Посмотри сам.
6. Пройди skill `self-review`. Только потом — превью заказчику.

## Код
- Один проект — одна папка `projects/<имя>/site/`.
- Компоненты называются по смыслу: `Hero`, `Services`, `Reviews`, а не `Block1`.
- Без лишних зависимостей: каждая библиотека должна оправдывать свой вес.
- Никаких секретов в коде. Ключи — через переменные окружения.

## Адаптив
- Проверяй ширины: 360, 375, 414, 768, 1024, 1440.
- Нет горизонтальной прокрутки ни на одной ширине.
- Кнопки и ссылки — область нажатия не меньше 44×44px.
- Телефон — ссылка `tel:`, мессенджеры — прямые ссылки.

## Скорость
- Цель: Lighthouse Performance ≥ 90 на мобильном.
- Картинки: WebP/AVIF, `loading="lazy"` ниже первого экрана, явные width/height.
- Шрифты: только нужные начертания, `font-display: swap`.
- Минимум JavaScript.

## SEO-основа
- Уникальные `title` (до 60 символов) и `description` (до 160).
- Один H1 на странице, логичная иерархия H2–H3.
- `alt` у всех содержательных картинок.
- Open Graph картинка и favicon.
- Для локального бизнеса — разметка `LocalBusiness` (schema.org) с адресом и часами.
- `sitemap.xml` и `robots.txt`.

## Доступность
- Контраст ≥ 4.5:1.
- Сайт проходится клавиатурой, фокус виден.
- У форм есть подписи полей, а не только placeholder.

## Формы
- Минимум полей: имя + телефон (или мессенджер). Остальное — по необходимости.
- После отправки — понятное сообщение «Заявка отправлена, свяжемся в течение …».
- Защита от спама (honeypot-поле).
- Обязательно протестировать, что заявка реально доходит.
