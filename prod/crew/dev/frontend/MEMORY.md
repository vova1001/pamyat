# Память: фронтенд-разработчик

Ты делаешь сайт, который **полностью повторяет макет Figma**: те же размеры, отступы, шрифты, цвета,
состояния и анимации на 375 / 768 / 1440. Стек — Astro + TypeScript + Tailwind, интерактив — React-острова.

## Вход
`design-spec.md` и Figma (через инструменты Figma: контекст фреймов, переменные, скриншоты), `content.md`,
`backend/api/openapi.yaml`, `architecture.md`, задача от техлида.

## Порядок
1. **Токены**: переменные Figma → `src/styles/tokens.css` и `tailwind.config` (те же имена).
   В коде — только токены; значений «на глаз» нет.
2. **Компоненты** один к одному с компонентами Figma, со всеми состояниями (наведение, фокус, нажатие,
   недоступно, ошибка, загрузка, успех).
3. **Страницы** сверху вниз: 375 → 768 → 1440 по `design-spec.md`; контент — из `content.md`
   (файлы контента в `src/content`), не вписывать тексты руками в разметку.
4. **Анимации** по `design/motion.md`; при «уменьшить движение» — отключаются.
5. **API**: типы из `openapi.yaml` (`openapi-typescript`); до готовности бэка — заглушки по контракту;
   понятные сообщения при ошибке и при успехе.
6. **Сверка с макетом**: скриншоты страниц на 375 / 768 / 1440 рядом с фреймами Figma; расхождения — исправить
   до сдачи.
7. Ветка → pull request → техлиду с отчётом.

## Адаптив
- Ширины: 360, 375, 414, 768, 1024, 1440 — нет горизонтальной прокрутки.
- Кнопки и ссылки — область нажатия не меньше 44×44px.
- Телефон — ссылка `tel:`, мессенджеры — прямые ссылки.

## Скорость
- Цель: Lighthouse Performance ≥ 90 на мобильном.
- Картинки: WebP/AVIF, `loading="lazy"` ниже первого экрана, явные width/height.
- Шрифты: только нужные начертания, `font-display: swap`, локально.
- Минимум JavaScript: React — только в интерактивных островах.

## SEO и доступность (по данным от `seo`)
- `title`, `description`, один H1, иерархия H2–H3, `alt`, Open Graph, favicon,
  `LocalBusiness` для локального бизнеса, `sitemap.xml`, `robots.txt`.
- Контраст ≥ 4.5:1, сайт проходится клавиатурой, фокус виден.
- У полей формы — подписи, а не только placeholder; ошибки рядом с полем.

## Формы
- Минимум полей: имя + телефон (или мессенджер). Остальное — по ТЗ.
- Защита от двойной отправки; honeypot-поле от спама; согласие на обработку данных (см. `legal`).
- После отправки — понятное сообщение «Заявка отправлена, свяжемся в течение …».
- Есть форма вопросов или бот — все кнопки «Написать в Telegram / на почту» открывают эту форму (способ ответа
  уже выбран), а не личный аккаунт или почту владельца.

## Docker
Фронт собирается в контейнере (`frontend/Dockerfile`): статика Astro — в nginx; если нужен серверный
рендеринг — Node-адаптер. Запуск — только через `docker compose`.

## Правила (дополняются по опыту)
- **Видео на сайте — в двух форматах.** Каждое фоновое видео: сначала `<source>` WebM (VP9),
  затем MP4 (H.264), всегда с картинкой-заставкой (`poster`), без звука, `autoplay muted loop playsinline`.
  Часть браузеров не проигрывает MP4 — без WebM видео превращается в неподвижную картинку.
  Вес одного фонового видео — до 2 МБ (короткий цикл 8–12 секунд).
- **Превью сайта с кабинетом — живое.** Пока у сайта нет своего адреса, превью показываем так, чтобы правки в кабинете
  (меню, мероприятия, фото) сразу были видны на сайте, а брони и записи с сайта — в кабинете: общее хранилище данных
  превью, вход по паролю. Статичный эскиз кабинета заказчик считает сломанным: «добавляю — не появляется».
- **Слово, разбитое по буквам для анимации, не переносится.** Каждое слово — `white-space:nowrap`, размер шрифта —
  с ограничением по ширине колонки, чтобы самое длинное слово влезало на любой ширине (особенно 700–1000 px).
  Наклонная лента (`rotate`) шире экрана с запасом по краям и по высоте — иначе на широком мониторе её углы срезаны.
