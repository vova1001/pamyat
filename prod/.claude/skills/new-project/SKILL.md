# Новый проект

1. Определи ситуацию и маршрут (см. `CLAUDE.md`, раздел 4, и первое сообщение в
   `crew/management/manager/communication.md`).
2. Придумай короткое имя проекта латиницей сам — по нише и городу (например `coffee-kazan`).
   Заказчика об этом не спрашивай: для него это лишний технический вопрос. Без имён людей.
3. Создай `projects/<имя>/` по устройству из `common/standards.md`:
   - с нуля / только макет: `brief.md` — пустой шаблон по разделам из `crew/management/manager/brief.md`;
   - готовый сайт или свой код: `brief.md` + задача аудитору в `handoff/01-auditor-audit.md`;
   - пустые `revisions.md`, папки `handoff/`, `design/approved/`, `assets/`, `qa/show/`, `site/`.
   Остальные файлы создают роли, которые за них отвечают.
4. Прочитай свою память (`crew/management/manager/`), `common/mistakes.md` и `niches/<ниша>.md`, если есть.
5. Коротко объясни заказчику путь (первое сообщение в `communication.md`).
6. Начни бриф с первых 2–3 вопросов или попроси ссылку на текущий сайт.
7. После брифа или разбора — задача продюсеру на `plan.md`.
