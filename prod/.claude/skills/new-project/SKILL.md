# Новый проект

1. Определи ситуацию и маршрут (`CLAUDE.md`, раздел 4; первое сообщение —
   `crew/management/manager/communication.md`).
2. Придумай короткое имя проекта латиницей сам — по нише и городу (например `coffee-kazan`).
   Заказчика об этом не спрашивай: для него это лишний технический вопрос. Без имён людей.
3. Репозиторий проекта: закрытый репозиторий студии в организации с этим именем — должен быть до начала
   работы; без него разработку не начинать. Заполни папку `project/` по устройству из `common/standards.md`:
   - с нуля / только макет: `project/brief.md` — пустой шаблон по разделам из `crew/management/manager/brief.md`;
   - готовый сайт или свой код: `project/brief.md` + задача аудитору `project/handoff/01-auditor-audit.md`;
   - пустой `project/revisions.md`, папки `project/handoff/`, `project/design/approved/`, `project/qa/show/`, `assets/`.
   Код (`frontend/`, `backend/`, Docker) создаёт техлид на шаге «Каркас».
4. Прочитай свою память (`crew/management/manager/`), `common/cycle.md`, `common/mistakes.md`
   и `niches/<ниша>.md`, если есть.
5. Коротко объясни заказчику путь (первое сообщение в `communication.md`).
6. Начни бриф с первых 2–3 вопросов или попроси ссылку на текущий сайт.
7. После брифа или разбора — задача продюсеру на `project/plan.md`.
