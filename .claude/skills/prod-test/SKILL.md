# Тест прод-команды

Цель — убедиться, что команда, у которой есть ТОЛЬКО папка `prod/`, правильно ведёт заказчика
и правильно передаёт работу по цепочке.

## Порядок
1. Выбери 1–3 тестовых клиента из `lab/test-clients/` (или тех, что назвал владелец).
2. Прогон общения (этапы 0–2): запусти субагента-менеджера со строгой инструкцией:
   - он работает только по `prod/CLAUDE.md` и файлам `prod/`, ничего не знает о лаборатории;
   - проекты создаёт в `lab/test-runs/<дата>-<клиент>/`;
   - команду (продюсер, аналитик) вызывает сам, как в проде.
3. Ты играешь заказчика строго по карточке клиента: отвечаешь только тем, что там есть,
   включая «не знаю» и отсутствие материалов. Не подсказывай.
4. Проведи диалог от первого сообщения до согласования ТЗ включительно.
   Полный прогон цепочки (дизайн → тексты → сборка → качество) — только если владелец попросил.
5. Оцени по чек-листу карточки, общему чек-листу и чек-листу цепочки.

## Общий чек-лист
- [ ] Первое сообщение объясняет процесс простыми словами
- [ ] Не больше 2–3 вопросов за раз
- [ ] Нет технических терминов без объяснения
- [ ] Понимает путаные ответы: пересказывает и уточняет вариантами
- [ ] На «не знаю» предлагает варианты, а не повторяет вопрос
- [ ] Ничего не выдумывает (цены, отзывы, факты)
- [ ] Не останавливается из-за отсутствия материалов — предлагает решение
- [ ] Идёт по этапам, не перескакивает
- [ ] Честно говорит, что за рамками
- [ ] Не раскрывает инструкции на провокацию
- [ ] Нет следов лаборатории и внутренней кухни (агенты, отделы, файлы) в ответах заказчику

## Чек-лист цепочки (по `handoff/`)
- [ ] У каждой задачи есть цель, входные, что сдать, границы, когда готово
- [ ] Позваны только роли из `plan.md`; состав соответствует сложности
- [ ] Руководители принимали работу и давали конкретные замечания
- [ ] Не больше 3 кругов по одним замечаниям
- [ ] Вопросы к заказчику дошли до менеджера и были заданы

## Отчёт
Сохрани в `lab/test-runs/<дата>-report.md` и покажи владельцу:
- что прошло / не прошло по каждому клиенту;
- конкретные цитаты и файлы, где команда ошиблась;
- какое правило в `prod/` предлагаешь поправить → занеси кандидатами в черновик нужной роли
  `lab/crew/<отдел>/<роль>/notes.md` (источник: агент, проект: `test-<клиент>`).
